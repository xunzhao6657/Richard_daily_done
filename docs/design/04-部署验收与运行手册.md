# 04 部署、验收与运行手册

## 1. 建议调度（本轮不注册）
|任务名|北京时间|动作|
|---|---|---|
|PostMarketReview-Collect|19:15每日|检查交易日，预采集/接口探针|
|PostMarketReview-Prepare|19:40每日|刷新；19:45冻结；模型至19:54；19:57 READY|
|PostMarketReview-Publish|20:00每日|仅发已验证本日READY；否则故障流程|
|PostMarketReview-Watchdog|20:02每日|核查三件套、hash、账本、耗时|
|PostMarketReview-Reconcile|次日06:30每日|只对未成熟/修订实际值发补评请求|
|PostMarketReview-Backup|20:15每日|独立review账本快照与恢复校验|
所有入口先检查对应目标交易日；非交易日SKIPPED。补评可在非交易日处理最近未完记录，不套用普通跳过。
20:00晨报Backup保留，复盘数据库隔离且publish不持长锁，不需要移动用户现有任务。
采用Windows任务计划程序本地服务，主机不依赖Codex在线或dsh会话。单独安装脚本不创建Codex重复定时自动化。
默认使用配置DPAPI密钥的同一账户Interactive；必须说明需保持登录、开机与联网。S4U/注销运行涉及联网凭据和DPAPI环境，必须实测而非宣称自动支持。睡眠唤醒配置受设备支持；关机无法保证准时，严格SLA需常开主机。
StartWhenAvailable=true；不补发过期日期为当天，所有补跑记录真实published_at与late。上午已过仍迟发的前日复盘默认不自动投递，仅存诊断。实施中配置最大补发窗口60分钟。
任务最大运行20分钟，prepare内部按deadline缩短；IgnoreNew只防同任务并发，跨任务仍需DB唯一键与文件锁。

## 2. CLI及配置
建议入口：python -m post_market_review --config config/review/runtime.json。
命令：doctor --redact [--probe-model]、collect --date、prepare --date --mode shadow、publish --date --mode shadow、watchdog --date、compare --date、reconcile、handoff --date、replay --run-id --offline、backup、status。
profile默认shadow，production必须显式安装并通过三件套/目录权限/真实数据验收，不绑定晨报Quant生产开关。
配置最少：timezone、calendars及有效期、schedule、deadlines、runtime limits、dataset policy paths、llm endpoint/model/secret_ref/budget、scoring rules、storage paths、mode、max_late_minutes、delivery.local_only=true。
doctor验证Python/锁文件、模块导入、账户、DPAPI是否能解密（不显示内容）、目录写权限、日历、Wind入口、各数据集能力、LLM接口、Word渲染及任务实际状态。
状态脚本区分NOT_REGISTERED与QUERY_ERROR/ACCESS_DENIED，不能吞权限错误后说未注册，更不能因此先覆盖全部任务。

## 3. 账本与安全
表：review_runs、receipts、observations、snapshots、derived_metrics、comparisons、claims、publications、handoff_items、source_incidents、evaluation_requests、budget_reservations。
每项有run_id/版本/时间/外键，出版唯一键含report_type。
锁记录owner_pid、host、started_at与过期策略；只能确认进程不存在后回收，不能按年龄盲删运行中锁。
保存原文SHA256和设计版本；schema迁移前SQLite backup，迁移事务回滚，部署不删历史。
建议运行日志90天、原始证据至少1年、发表工件与规则长期留存；具体存储预算与供应商许可优先，超过保留期采用显式清理程序，不混入日常publish。
本地密钥DPAPI+ACL；不把用户此前在聊天发过的Wind Key写入任何文件。默认使用现有Wind认证链，新的凭据仅经本机隐藏输入设置。
连续3个适用交易日同数据集失败标“待修复”；休市/未到发布时间不累计故障天数。
不自动发邮件/聊天。watchdog先写本地告警与非零退出码，外部通知只有明确渠道接收人后实施。

## 4. 验收矩阵
|ID|场景|通过条件|
|---|---|---|
|A01|有效交易日/休市/未知年份|仅交易日运行；未知日历硬失败|
|A02|正常三件套|七节同序、数据一致、涨红跌绿、中文Word可读|
|A03|Wind宕机/单项缺失|不编造；状态正确；有故障/部分三件套|
|A04|双源偏差边界|等于阈值不冲突，大于冲突；同上游不独立|
|A05|日期与单位不一致|不能比较或汇总；不自动误乘万元/亿元|
|A06|两融T-1/宏观修订|标签保留日期和版本，不能作当日数据|
|A07|19:45截点|恰好可得允许，晚1毫秒隔离；重放不看新值|
|A08|温度计|手算五因子一致；历史不足/分母零/冲突返回null|
|A09|预测不可用|NOT_PREDICTED/NA；不从Markdown制造预测|
|A10|hash篡改/晚发晨报|初判拒绝；正式评分不得写入|
|A11|模型编造数字/实体/引用|拒绝，或按规则部分降级；不存在token不得渲染|
|A12|消息晚于收盘|禁止当日强因果；可作次日风险观察|
|A13|外发注入|凭据藏在reason/嵌套字段、本地路径、额外字段/全文均出站前阻断|
|A14|LLM超时/429/额度耗尽|有界重试、模板回退；不拖延发布|
|A15|重复触发/并发/进程崩溃|唯一发表；恢复对账；不留下成功假记录|
|A16|Word导出失败/目录拒绝访问|不记录正常成功；缺件明确，本地告警可见|
|A17|与08:00晨报同机运行|已有任务/密钥/发布文件不变，共享预算不超限|
|A18|次日交接过期/篡改|晨报忽略并登记；不将自然语言当指令执行|
|A19|重放与恢复|离线hash检查+同版本文档重渲染通过；SQLite integrity_check=ok|
|A20|任务真实执行|实际账户执行一次；核验动作、触发器、last result和产物，不只看注册|
|A21|旧文件同名|拒绝覆盖，正确记录冲突与修订位置|
|A22|供应商schema变化|保留raw并隔离，不静默空成功|
|A23|预算并发|晨报/复盘同时预留仍不超过账户总配额|
|A24|公开阅读副本半写|无提交manifest时不可消费；恢复后全套hash一致|

测试使用隔离临时目录与TEST_ONLY标记，不能往正式中文目录写fixture。完成单元/契约测试后做一次真实shadow端到端，再作用户范围内生产部署。
证据覆盖率=带可核验来源的已发表事实数/已发表事实总数，必须100%；“来源存在”不等于语义正确，至少审阅正常/缺失/冲突3份真实或隔离标注报告。不得把测试全绿等同投资判断有效。

## 5. 实施阶段与交付记录
M0资产盘点：原文hash、旧任务只读查询、现有能力矩阵、路径冲突检查。
M1离线完整链：schema/账本/日历/模板/三件套/发布崩溃恢复。
M2真实数据：逐集接口发现、最小探针、单位日期核验、raw回执。
M3专业分析：温度计、结构特征、版本规则、晨报比较。
M4DeepSeek：合成探针、字段白名单、授权策略、真实证据链。
M5发布与闭环：次日包、三件套视觉验收、补评兼容、备份恢复。
M6影子定时：实际注册和一次任务执行；至少3个交易日观察证明稳定性，观察未满如实标待验证，不提前宣称SLA达成。
每阶段更新IMPLEMENTATION_STATUS_REVIEW.md与需求映射CSV：代码位置、测试ID、实际接口证据、缺失、下一步。能力受外部数据限制时继续完成其它模块，保留明确缺失，不能虚构完成。
