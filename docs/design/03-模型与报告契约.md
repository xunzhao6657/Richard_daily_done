# 03 模型与报告契约

## 1. DeepSeek边界
使用https://api.deepseek.com，model=deepseek-v4-flash。复用当前账户DPAPI读取器，不在新配置复制密钥。Wind凭据与DeepSeek凭据相互独立。
部署时用最小合成/chat/completions实际调用检验JSON输出、thinking参数、超时、finish_reason与returned_model；请求模型固定为deepseek-v4-flash。供应商若返回不同后端标识，只接受配置中经实测登记的精确白名单，保留请求/返回模型审计，禁止通配符和自动替换其他模型。已有晨报探针不替代复盘大证据包契约验收。
建议temperature=0.2、max_tokens=6000、单次请求90秒、最多2次模型请求（含一次修复），19:54模型硬截止，保留导出时间。正式预算账户级日输入100000、输出20000，复盘子配额输入40000、输出12000；实施前对照现有晨报预算，不能暗中降低晨报额度。预算预留并发原子化，晨报和复盘共用总账，子账区分purpose。
HTTP 401/403立即降级；429/5xx在预算和截止内重试；非法JSON/引用只允许一次有界修复；超时回确定性模板。
只向模型发送按字段白名单重建的evidence DTO。不得仅靠删除receipt几个键：错误文本可能含路径/请求回显。错误只映射本地枚举，额外字段拒绝，嵌套字符串做凭据/路径检测。
现有授权明确覆盖已登记Wind标准化事实；新增行业、资金、新闻、机构全文不因拥有API Key自动扩展许可。source_policies须逐数据集记录允许摘要/数值范围；不明确者可本地展示、不可外发。复用已覆盖事实无需反复要求授权。

## 2. 数据结构（全部实现为严格JSON Schema，additionalProperties=false）
review.snapshot.v1：
run_id,report_date,cutoff_at,created_at,mode,observations[],derived_metrics[],source_states[],snapshot_hash。
review.evidence.v1：
snapshot_hash,facts[{evidence_id,label,display_value,trade_date,available_time,source_label}],metrics[],comparisons[],events[],allowed_section_ids。
review.research.v1：
prompt_version,evidence_hash,claims[],watch_items[],limitations[]。
claim：
claim_id,section_id,claim_type,text_template,evidence_ids[],uncertainties[],causal_strength。
claim_type为FACT_SUMMARY/INTERPRETATION/HYPOTHESIS/RISK；causal_strength=DESCRIPTIVE/ASSOCIATION/HYPOTHESIS，不准无证据强因果。
正文数字只允许{{fact:F001}}、{{metric:M001}}、{{comparison:C001}}引用，不允许自由数字、数字汉字伪预测、任意URL。股票名称/代码从实体表注入，数字扫描在token展开前执行。
watch_item：
watch_id,entity_id,hypothesis_template,variable_id,trigger_rule_id,invalidator_rule_id,evidence_ids[],valid_until_session。
trigger_rule_id引用代码生成的允许规则；没有量化阈值可为null并明确“待观察”，模型不能虚构目标点位。
review.document.v1：
title,report_date,status,narrative_status,cutoff_at,sections[7],source_notes,limitations；统一供三种格式渲染。
review.comparison.v1：
comparison_id,forecast_publication_id,forecast_sha256,target_id,forecast_value,actual_observation_ids,actual_value,rule_version,verdict,reason_codes,is_preliminary。
review.handoff.v1：
review_publication_id,review_sha256,next_session,available_at,watch_items[],evidence_refs[],limitations[],expires_at。
publication.v1复盘专用：
publication_id,report_type,report_date,slot,mode,run_id,published_at,late,artifact_hashes,source_snapshot_hash,forecast_ref,revision_of,status。

校验不仅判断ID存在：数字token必须在该claim引用集合内；数字符号/日期单位由模板控制；截点、消息时序、观察规则、对象与目标对应关系均确定性校验。ID正确不证明推理正确；语义不充分的句子删除或降为HYPOTHESIS。记录原始模型输出（脱敏本地）、通过/拒绝claims及理由，支持离线按同一文档树再渲染，禁止声称hash校验等于语义审核。

## 3. 晨报预测初判
先由publication索引定位同日已发表晨报并验证forecast文件hash；不能读staging作为已发布预测，不能优先取较晚更漂亮的预测。
正式/影子不混用。若正式晨报不存在可显示影子实验比较，但所有结果标SHADOW且不计正式绩效。
NOT_PREDICTED：目标原本UNAVAILABLE。NA：实际值/可比规则缺失。INVALID_FORECAST：hash不符、晚于目标观察窗口、规则不明。
若方向有预注册flat_band_bps则代码判方向；没有则不临时设阈值。
点位和成交额记录点误差、区间覆盖（仅原预测有区间时）；相对误差分母为0返回NA。
风格、行业、资金、触发、港股须事前taxonomy/horizon/单位/阈值齐全，否则不猜“部分命中”。trigger无分钟数据则NOT_EVALUABLE_INTRADAY。
“命中/部分/脱靶”只由forecast绑定的规则ID映射；没有事前规则仅显示客观误差与NA，不事后挑宽阈值。
复盘初判只写review比较表；正式评分由兼容后的独立evaluate更新版本化评价表，保留actual revision。不得改forecast、晨报正文或历史分数。
现有18:30评价先保留；复盘使用其结果时注明实际值版本，晚到值安排次日补评事件而非静默覆盖。

## 4. 三件套与闭环
七节严格依原文：当日市场定性、盘面结构、情绪观察、晨报预测初步对照、异动与消息面、明日关注点、数据源状态。
每一判断显示证据ID，可定位本地audit与原始回执；公开阅读版仅安全来源名称/URL，无凭据和内部路径。
HTML用真实表格/标题，UTF-8，escape不可信内容；红#C62828涨、绿#15803D跌、灰中性，并附↑+/↓-，不能只靠颜色。
Word用独立锁定版本python-docx等导出器，中文字体回退与A4分页，表头重复、数值单位一致；不可复用目前仅pre标签的晨报HTML实现而称完成。
三格式消费同一ReportDocument；自动比较标题、段落、表格数值集合，人工/渲染检查长表、中文换行、颜色、跨页与空值。
无LLM仍生成完整七节模板；来源故障则故障三件套。DOCX失败时普通发布阻断，可另产EMERGENCY_PARTIAL与明确缺件清单，独立事件，不占正常发布成功计数。
交接包只含经审核观察项与引用，不含对下游的自由指令。次日晨报检查next_session、有效期、哈希和available_at≤晨报截点，重新验证事件更新；不能把昨日判断当今日事实，也不反馈到训练标签。
